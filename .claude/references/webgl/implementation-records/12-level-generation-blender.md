# レベルの組み立てとライトマップベイク（Chaotic Customer 2 の Zone_1、Blender）

## 役割
ステージ = ファンゲーム『Chaotic Customer 2』のマップ `Chaotic_Customer_Zone_1`（地上の迷路と地下鉄の駅。`.claude/references/chaotic-customer-2/README.md`）を、その CUE4Parse の書き出し（`cc2_reference/`、git の対象外）の配置とメッシュで組み立て、ライトマップを焼いて `assets-src/level/` に書き出す。3 段で行う。
- `scripts/cc2/layout.py`（Blender 同梱の Python。`ue.py` を使う）: 書き出しの配置・当たり・灯・ボリューム・マテリアルを読む前処理 → `assets-src/cc2/layout.json`（git の対象外）と git 管理の `assets-src/level/stage.json`。
- `scripts/blender/build_cc2.py`（Blender 5.1、ヘッドレス）: layout.json どおりに書き出しの glb を置き、タイルに結合し、ライトマップのページを Cycles で焼き、反射キャプチャと SkyLight の全天球を描いて `level.glb`・ライトマップ・`level-meta.json` を書く。衝突の入力の三角形も書く。
- `scripts/cc2/colliders.mjs`（Node）: その三角形から衝突の箱と階段の坂、巡回点を作る → `assets-src/level/colliders.json`。
地上の迷路の床を Blender の z 0、地下鉄のホームを −21.03 m に置く（階段で物理的につながっているのでずらさない）。2026-09-13〜14 の原作『Dark Deception』の Hotel（`scripts/hotel/layout.mjs`・`build_hotel.py`）と、それ以前の手続き生成の館は削除した（ユーザーの指示。git の履歴に残る）。ほかに色補正の LUT のデータ化（`grading-luts.mjs`）もここ。

## 公開インターフェース
- `npm run assets:cc2-layout` = `blender -b --factory-startup -P scripts/cc2/layout.py`（Blender は同梱の Python と USD の `pxr` のためだけ。約 10 秒）。入力は `cc2_reference/`（環境変数 `CC2_REF`、既定 `<repo>/cc2_reference` = CUE4Parse の書き出しへのシンボリックリンク。無ければ「cc2_reference not found」で終了）。
- `npm run assets:cc2-bake` = `blender -b -P scripts/blender/build_cc2.py`。`--` 以降のオプション（`parse_args`）: `--out DIR`（既定 `<repo>/assets-src/level`）、`--size N`（ページの一辺、既定 4096。4 の倍数でなければ終了）、`--samples N`（間接光の spp、既定 2048。直接光は `max(16, min(N, max(256, N/2)))`）、`--density`（目標のライトマップの px/m、既定 12）、`--max-pages`（既定 4）、`--no-bake`（組み立てと書き出しだけ。ページごとの `texelsPerMeter` が前と同じなら焼いたライトマップのスケールを引き継ぐ）、`--no-denoise`、`--cpu`、`--preview DIR`（地上と地下の俯瞰図）、`--captures` / `--no-captures`（反射キャプチャと空の全天球を描くか。既定は焼くときだけ）、`--capture-samples N`（既定 256）、`--sky-only`（SkyLight の全天球だけを `--out` の `captures/Sky.hdr` に描き、そこの `level-meta.json` の `sky` に `file` と `average` を書いて終わる。約 2 秒）。
- `npm run assets:cc2-colliders` = `node scripts/cc2/colliders.mjs`（約 3 秒）。
- `npm run assets:cc2-luts` = `node scripts/cc2/grading-luts.mjs`。
- `raster.mjs` の export（`raster.d.mts` が型、`tests/cc2-raster.test.ts` が検査）: `CellGrid`、`mergeRects`、`clearance`、`spreadPoints`。`heightfield.mjs` の export（`heightfield.d.mts`、`tests/cc2-heightfield.test.ts`）: 下記。

### build_cc2.py（組み立てとベイク）
1. **マテリアル**（`make_materials`）: layout.json の `materials` ごとに Principled BSDF。アルベドは `materials.json` の `bakeAlbedo`（13 記録。人物の絵はワサミに差し替え済み）、無ければ書き出しの PNG（`UVMap`）、無ければ `constColor`。α（マスクの色の α、デカールのマスク）を Alpha に、`opacity` の定数、ほかの半透明（ガラス）は Alpha 0.35 で光を通す。
2. **置く**（`source` / `place`）: 配置の glb を 1 回ずつ `import_scene.gltf`（`merge_vertices=False`）して隠したコレクション `_sources` に置き、配置ごとにメッシュを複製。読み込むのは `sectioned_glb` の写し（一時フォルダ）: JSON のマテリアルをプリミティブごとに別の `__section_<i>` に替える（書き出しは区画にメッシュ資産の既定のマテリアルを付けていて、`WorldGridMaterial` のように同じ名前の区画が Blender の読み込みで 1 つのスロットにまとまり、2 つ目以降のスロットの UE のマテリアルが失われていた。配置 1,239 のうち 561）。UV は 0 番を `UVMap`、`lightmapUV` 番を `Lightmap` にしてほかを消す。Blender のスロット `__section_<k>` を区画 k のスロット `sections[k]` に当て、そのスロットの layout のマテリアルにする（`sections` が足りなければ k）。`matrix_world = matrix @ インポーターの物体行列`。ライトマップ UV が無いか潰れていれば Lightmap Pack（`unwrap(smart=False)`。現行 2 個）。
3. **デカール**（`import_decals`）: 書き出しの `_Decals.usda` を `wm.usd_import`（マテリアルなし）し、layout の `decals` にあるものだけを床の持ち上げ（+3.35 m）をして残し、layout のマテリアルを付け、影を落とさず、Lightmap Pack する（現行 39 個。投影面の無いデカールは書き出しに無い）。
4. 静的な物の変換をメッシュに焼き、水平の大きさが `SPLIT_SIZE`（48 m）を超えるもの（地下の駅 `Metro2` 13.7 万面 → 12 片、地上のゾーン本体 `Zone_1_ENHANCED_2` 53 万面・12 万 m² → 62 片）を面の中心の `LEVEL_TILE`（24 m）のマスごとに分け（`split_big`。bmesh で他のマスの面を消した写し）、片ごとに Smart UV Project（66°、余白 0.004）でライトマップ UV を作り直す。1 メッシュのままではタイルの視錐台カリングも影の描画対象の絞り込みも効かず、1 枚のアトラスでは 8.5 px/m にしかならなかったため。
5. **ライトマップのページ**（`assign_pages` / `pack_lightmap`）: 焼く物（静的・デカール・焼く動く部品）の世界の面積の合計から、`--density` に要るページ数（`PAGE_FILL` 0.7 の充填で、`--max-pages` まで）を決め、24 m のマスを（ゾーン・行・列の順に）面積がほぼ等しくなるようにページへ振り分ける。ページの中は、各物体のライトマップ UV（0..1 の配置）を、世界での表面積の平方根 × 密度の正方形（最小 `MIN_RECT` 6 px、最大は一辺の `MAX_RECT_FRAC` 0.5、内側に `RECT_PAD` 2 px）へ縦横比を保って縮め、高さ順の棚詰め（`shelf_pack`）で収まる最大の密度を 2 分探索する。16.3 万 m² に 4096 のページ・`--density 10` で 2 ページ、13.2 px/m（2026-09-14 の本番のベイク）。
6. **タイル**: 静的な物とデカールを中心で（ゾーン・ページ・反射キャプチャ・24 m のマス）ごとに結合して `Level_Static_NN`（現行 103 個、244.3 万三角形）。キャプチャに入らないタイル（地上の迷路すべて）は −1（実行時は SkyLight の全天球）。
7. **動く部品**: 1 つずつ `<role>__<actor>__<comp>` の名前で、変換を焼かずに部品の原点に残す（実行時に回したり動かしたりするため）。焼かない役割（障壁の板・車・点滅する箱）は影を落とさない。
8. **衝突の入力**（`write_tris`。タイルに結合する前）: 当たりのある静的な物（`collision` が真。デカールは入れない）と列車（`train` / `trainDoor`）を、UE の当たりの形（layout の `collisionShapes`）で `assets-src/cc2/tris.bin`（float32 × 9 / 三角形、Blender の m）と `tris.json`（オブジェクトごとの役割・ゾーン・種類・範囲）に書く。`complex` のメッシュと切った片は描画の三角形、`simple` は凸包と箱の三角形を (x, −y, z) / 100 にして配置の世界行列（`place` が `ob["world"]` に残す。変換を焼いた後も使う）で、`none` は書かない。現行は simple 708・complex 106 オブジェクト、88.6 万三角形。
9. **ベイクの灯**（`setup_lights`）: layout の灯すべて。点とスポットは `4π × cd` W、矩形（Blender の AREA の RECTANGLE、`size` / `size_y` = UE の幅と高さ、−Z = UE の向き、Y = UE の上）は `π × cd` W（UE の矩形の強さは法線方向の cd で cos で落ちる片面の拡散体とみなす）、扉の角度 a を Blender の spread 2a（推定）。どれにも UE の減衰の窓 `saturate(1 − (d/r)⁴)²`（`ue_falloff`: 灯のノードで Light Path の Ray Length から作り、Emission の Strength に掛ける）。色は sRGB → 線形（温度を使う灯はプランクの式）。ワールドは UE の SkyLight（`sky_of`）: キューブマップ `HDRI_Epic_Courtyard_Daylight.hdr` × Intensity 0.75 × LightColor（線形）を地平線の上、LowerHemisphereColor 0.05 を下に。この単位で、1 cd の点光源の 1 m 下の白い板は DIFFUSE の焼き込みで 1/π（白い面の輝度）になり、UE の輝度と同じ（09 記録の手動露出がそのまま合う。2026-09-14 に Blender で確かめた）。
10. **ベイク**（`bake_lightmaps`）: ページごとに、そのページの物だけを選んで焼く。`CYCLES`、Metal GPU（無ければ CPU）、`max_bounces` 8 / diffuse 5 / glossy 2、`sample_clamp_indirect` 8。共有マテリアルに画像ノードを 1 つ足して、カバレッジのマスクを `ROUGHNESS` 1 spp、`DIFFUSE` を `{"DIRECT"}` と `{"INDIRECT"}` で別々に（margin 16、EXTEND）焼く。金属は一時的に金属 0・粗さ 0.3 以上。焼かない動く部品は隠す。OIDN（コンポジタの Denoise）→ 負値を 0、`full = direct + indirect`、`AMBIENT` (0.0008, 0.0010, 0.0013) を足す（indirect にも）、ページごとの `lightmapScale` = ジオメトリのテクセルの max(r,g,b) の 99.5 パーセンタイル。`save_exr`（half、ZIP、往復の相対誤差 1 % 超で例外）、`save_png_encoded`（`clamp((linear / scale)^(1/2.2))` の 8bit PNG。全部と間接光で同じ `scale`）で `lightmap_<page>` / `lightmap_indirect_<page>` を書く。1024 のページ 4 枚・64 spp の試しのベイクは約 34 分（M4 Pro の Metal）。
11. **反射キャプチャ**（`render_captures`。`--captures` のとき）: キャプチャ（地下の箱 2 つ）ごとに、その位置の全天球のカメラ（`PANO` / `EQUIRECTANGULAR`、`CAPTURE_WIDTH` 512 × 256、`clip_start` 1 cm、向き `CAPTURE_ROTATION` = −Y 向き）で Cycles の `samples` spp・OIDN の Radiance HDR `captures/Capture_NN.hdr` を描く。発光は layout の `emissiveColor`（発光テクスチャだけのものは白）× `emissiveStrength` ÷ `CAPTURE_SCALE`（1.0: 実行時のキャプチャとライトマップの強さが 1）。UE はキャプチャも片面のマテリアルの裏を描かないので、両面でないマテリアルはこの間だけ Geometry の Backfacing で Transparent BSDF に混ぜる。向きは Babylon の `HDRCubeTexture` が全天球の中央の列を +Z 面へ置き、glTF の取り込みで Blender の −Y が Babylon の +Z になるので −Y。`capture_average` が UE の AverageBrightness（輝度 0.3・0.59・0.11 を立体角で重み付けした平均）を出す。続けて、ワールドだけを（全部の物を描かずに）同じカメラで 16 spp（`SKY_SAMPLES`）描いた `captures/Sky.hdr`（`render_sky`。キャプチャの届かない面が映す。07 記録）。
12. **書き出し**: マテリアルから画像ノードと UV ノードを消し、`_sources` を消して `export_glb`（GLB、画像なし、Y-up、extras あり、接線なし。頂点の色は build-level.mjs が外す。13 記録）。`level-meta.json`: `lightmapPages`（ページごとのファイル・`lightmapScale`・`texelsPerMeter`・統計）、`lightmapOf`（タイルと焼く動く部品 → ページ）、`tiles` / `tileZones`、`floors`（迷路 0・地下 −21.03 m）、`lamps`（layout の灯すべて: 位置・向き・色・cd・W・半径・影・持ち主の役割・発光の動く部品 `glow`・矩形の大きさ・スポットの円錐）、`bakeLights`、`sky`（`sky_meta`: SkyLight の値と、描いたなら `file`・`average`）、`captures`、`captureOf`、`moving`（動く部品の役割・アクター・焼くか）、`captureRender` など。`--no-bake` の組み立てだけで約 42 秒。

### colliders.mjs（衝突の前処理）と heightfield.mjs・raster.mjs
入力は `assets-src/cc2/tris.bin` / `tris.json`（`build_cc2.py`。`--no-bake` で作れる）と `assets-src/level/stage.json`。無ければ手順を出して終了。
- **迷路**（床 = z 0）: 10 cm の格子（`raster.mjs` の `CellGrid`）。±`FLOOR_TOL`（0.3 m。縁石 15 cm と減速帯 74 個を含む）の傾き 45° 以下（`UP_NZ` 0.7）の上向きの面を床に、`BAND`（0.35〜1.9 m）に掛かる面を障害物に。障害物の判定は三角形をセルで切り取った高さ（`clipZRange`）で行う（天井に沿って斜めに下る梁の側面のような面が真下のセルを塞がないように）。`stage.json` の `hiddenWalls` も障害物。歩ける所とそれ以外を矩形に併合して床の箱（−0.2〜0）と壁の箱（〜`WALL_TOP` 3.5）。ただし地下の階段の上の段が迷路の高さに近い所（`OPENING` −2.2 m より上の地下の床の上とその周り 1 セル）には壁を置かない（階段のマスの高さは、ならす前の段の高さとならした坂の高さの高いほう。実行時が歩くのは坂で、段の縁では段より最大約 0.4 m 高い）。
  - **壁の箱の底**: 既定は 0。ただし地下の歩く床（−`FLOOR_TOL` 以下の地下の床。坂のマスは上と同じく高いほう。迷路と同じ高さの床は数えない）の上にあり、塞ぐ面のある壁のマスは、底を「そのマスを塞ぐ面の一番低い所 `blockLow`」と「`WALL_NEAR`（4 セル）以内で一番高い歩く床 `nearTop` + `WALL_HEAD` 2.1 m」の低いほう（0 未満にしない。0.1 m 単位で切り上げ）にし、底の高さごとに矩形に併合する。塞ぐ面の無い壁のマス（何も無い所、`hiddenWalls`）は 0 から。最後の階段の上の傾いた天井（その上で約 1.8 m）の所に 0 からの壁があり、坂の上のカプセルの頭が当たっていた（坂ではカプセルが真下の坂より約 0.16 m 浮き、0.32 m 張り出す）。
- **地下と階段**（`SpanGrid`）: `METRO_TOP`（−0.2 m）より下の三角形の範囲に、セルごとに床の高さを最大 `MAX_SPANS`（12。高い方を残す。`Fencing_Cube_77` の横木の上面 10 枚がホームの床を押し出していたので 4 から増やした。いまは `Fencing_Cube_77` は動く部品で三角形に入らない）と、`Z_MIN` −24〜`Z_MAX` 3 m を 10 cm ごとのビットで何かが占める高さを持つ格子。床から `CROUCH_BAND`（0.55〜0.88 m。ファンゲームのしゃがんだプレイヤーの高さ 0.9 m。本作にしゃがみは無いが、塗りはこの帯で行い、立っては通れない床は下の `low` と `overhead` で扱う）に何も無い床を歩けるとし、開始地点（checkpoint 1）から、隣の床のうち高さが最も近く `STEP`（0.4 m）以内のものへ 4 近傍で塗る（`floodSpans`）。塗りは 2 段: まず `METRO_TOP` 以下の床だけで（ホームと階段の全段）、次にその届いた所から上（階段の上の迷路の床）へ、先に取ったマスを保ったまま続ける（`floodSpans` に 1 段目の `reach` を渡す。1 マスは 1 つの床しか持てず、迷路の床に早く届くと下の段のマスを取ってしまった）。`METRO_BAND`（0.55〜1.9 m）まで空いていない届いた床（立ったままでは通れない低い床 `low`）の上に、床から `CROUCH_BAND[0]`〜`METRO_BAND[1]` の高さで掛かる三角形は、そのままの形で `overhead` のメッシュにする（そこの天井: 立ったプレイヤーは止まる）。以前この下がしゃがみでだけ通れる床だった出口の板と `Fencing_Cube_77` は、いまは動く部品（上の「板張りの通り道」）で三角形に入らない。届いた床のうち同じ高さのセルが `FLAT_CELLS`（2,000 = 20 m²）以上ある高さは平らな床として床の箱、残り（段・踊り場。`isRamp`）は坂: 高さを半径 `SMOOTH`（3 セル）でならし（`smoothHeights`）、`RAMP_STEP`（2 セル）ごとの頂点の三角形メッシュ `ramps`。
  - 坂の網がかぶるマス `underRamp`（`RAMP_STEP` の網の目のうち、その下か隣に坂のマスがあり 4 隅に高さのあるもの）は平らな床の箱から外す（網がそこの床。箱の縁が網より 0.10 m 上に出て、坂を上って来るカプセルが越えられなかった）。
  - 坂が上って行く先の床の縁 `junction`: 坂のマスと 4 近傍で隣り合う、坂でないマスのうち、地下の平らな床か迷路の床（高さ 0。障害物の無い迷路の床のマス）で、その坂のマスのならした高さより上で `STEP` 以内のもの。`vertexAt` は坂の頂点を、`RAMP_REACH`（10 セル）以内の縁のマスへ、そのマスから 1 m ごとに `RAMP_RISE`（1 m = 45°）低い高さまで持ち上げる（下げはしない。下の床に合わせると最初の網が 50° より急になる）。ならした坂は上る先の床より低く終わり（駅の上の床で 16 cm、迷路の床で 30 cm）、実行時のカプセルの丸い底が越えられる約 11 cm を超えていた（Babylon の step-up は段の角に乗って諦める）。持ち上げた後は最後の階段の上端が −0.60 → −0.40 → −0.20 → 0.00、下の階段の上端が −10.02 → −9.92（床の箱の上面）でつながる。隣の坂より `STEP` を超えて高い床（踊り場の縁）は縁にしない。壁は、届いていないセルのうち 2 セル以内に届いた床があるものを、その最も高い床の 1 m の帯ごとに併合した箱。
- **確認**: 迷路はチェックポイント 2 から 4 近傍で塗り、どのシャードも届くか（`unreachableShards`）、階段が開始地点と迷路をつなぐか（点の塗り `joined`）、それを体の幅でも（`bodyJoined`: 半径 `BODY_RADIUS` 0.3 m の円の中がすべて、高さの差 0.6 m 以内の床のマスだけを、段差 `STEP` 以内で開始地点から塗り、迷路の歩ける床に着くか。高さは実行時が歩く面〈階段のマスはならした坂の高さ、平らな床はそのまま、地下が届いていない迷路の床は 0〉。点の塗りは体の通れない隙間を通すので、開始地点のホームから出られないステージを見逃していた）。駅の柵と板張りの通り道は動く部品で三角形に入らないので、通れる扱い。体の幅の確認も、立ったままでは通れない低い床（`low`）は通れない扱い（下の経路と同じ。本作にしゃがみは無い）。どれかが崩れれば終了コード 2。調べるための出力: `DEBUG_BODY=x0,x1,y0,y1,s`（体の確認の平面図。`#` 床なし・`.` 狭い・`o` 空いているが届かない・英字は届いたマスの床の高さ〈a = −22〜−21 m … v = −1〜0 m〉）、`DEBUG_CELLS=x0,x1,y0,y1`（マスごとの床の高さ〈届いた床に *〉と、その上で最初に埋まっている高さ）、`DEBUG_MAZE=x0,x1,y0,y1`（迷路のマスの平面図: `B` 塞がれている〈`BAND` に物〉・`F` 床・`O` 階段の口・`#` 壁〈歩ける物なし〉）。
- **経路** `route`（`scripts/flow-check.mjs` が歩く）: 開始地点から、ホールのトリガー（stage.json の `triggers.chase` を各辺 0.5 m 内側に縮めた範囲で、高さ −`FLOOR_TOL` 以上のマス）までの最も安いマスの道を、体の確認と同じマスのうち立って歩けるもの（`roomy` で、段差 `STEP` 以内の 4 近傍。立ったままでは通れない低い床 `low` は除く。本作にしゃがみは無い）の上のダイクストラで求める。1 歩の値は 1、`ROUTE_ROOM`（0.5 m）以内の床がそろっていない（高さの差 0.6 m 以内の床が無いマスがある。壁際）なら + `ROUTE_TIGHT` 4。道を、次の点までまっすぐ見通せる（半セルごとに、段差 `STEP` 以内・`roomy`・0.5 m 以内の床がそろい、`low` でない）点に間引く。駅の柵・板張りの通り道・障壁・扉は動く部品で三角形に入らないので、道はそれを通り抜ける。高さは体の確認と同じ実行時が歩く面。
- **巡回点と敵の出現**: 迷路の届く所のうち障害物から `WAYPOINT_CLEAR`（0.5 m）以上のセルに、チェックポイント 2 から `WAYPOINT_SPACING`（9 m）の最遠点の順次選択（`spreadPoints`）。敵の出現点は、届く所に無ければ 0.4 m 以上空いた最寄りのセルへ寄せる。

## 既知の制約・注意点
- ファンゲームのベイク済みライティングは使わない（`_lightmaps/` の 617 区画のうち中身があるのは 57 だけで値もごく暗い。灯の大半が Stationary / Movable）。UE5 の Lumen が使われたかは確定できない。
- UE の減衰（減衰半径の窓）は灯のノードで再現するが、UE の `1/(d² + 1)`（cm）の +1 は入れていない。矩形の灯の扉の角度（barn door）を Blender の spread にする換算は推定。
- ベイクは時間がかかる: 4096 のページ 2 枚・64 spp で数時間（ページごとの準備に 8〜12 分、直接光 11 分、間接光 18 分ほど）。
- 高さの霧・ポストプロセスボリュームの色の調整は焼いていない（実行時のポストプロセス。09 記録）。
- 実行時のカプセル（Babylon の `PhysicsCharacterController`、`maxStepHeight` 未設定）は約 11 cm の段しか越えられない（UE の MaxStepHeight 45 cm に合わせて 0.45 にしても、step-up が段の角に乗って諦めた）。坂と床のつなぎ目（`underRamp`・`junction`）と迷路の壁の底はデータの側で段と低い天井を無くしている。点の塗りと体の幅の確認は段の高さ `STEP` で見るので、この種の段は見逃す（`route` を flow-check が歩いて確かめる）。
