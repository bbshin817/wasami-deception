# WASAMI DECEPTION — 垂直スライス（Babylon.js）

UE4製ホラー『Dark Deception』の見た目を Web で再現できるかを確かめる、一人称3D探索の垂直スライスです。原作の特徴である強いモーションブラーとリアルなPBR質感を再現し、舞台にはファンゲーム『Chaotic Customer 2』（UE5.4）の最初のステージ Zone_1（地下鉄の駅・階段・地上の迷路）を移植しています。以前の舞台（原作の Hotel）で作った描き方（UE のフィルム調のトーンマップとボリュームの色補正、ブルーム、SSAO、SSR、反射キャプチャとライトマップの混合、ライトマップの運び手、影付き3灯のプール、霧、深度の代理）はそのまま持ち越しています。

- **描画**：Babylon.js 9.26（既定は WebGL2。`?render.preferWebGPU=true` で WebGPU）
- **物理**：Havok
- **開発環境**：Vite 8 + TypeScript
- **対象**：デスクトップのみ。モバイルには対応していません。
- **ゲームの流れ**：ファンゲームのレベルの流れに倣っています。列車が着いて扉の開いた地下鉄のホームから始まり、ダッシュの障壁を壊して階段を上がると、地上の迷路の広間でチェックポイントが保存され、1秒後にワサミの姿の敵が10体放たれます。迷路に原作の位置のまま散らばるシャード（見た目はワサミ餅）301個に触れて回収すると、シャードの障壁が割れ、奥の配電盤が使えるようになります。配電盤を使うと暗転して脱出（チェックポイント4）が始まり、背後からトラックが走り出し、マネキンの群れ（本作ではワサミ）が追ってきます。脱出のゾーンを抜けて配電盤の場所まで戻るとクリアです。制限時間はありません。ライフは3つで、捕まるか罠で死ぬと死亡画面のあと、集めたシャードを保ったまま最後のチェックポイント（ホーム・広間・脱出の開始）からやり直しです。ライフがなくなるとゲームオーバーです。
- **参考映像**：見た目は `dark.mp4`、基本操作は原作の調査に合わせています（下記参照）。

## 起動

Node.js 22.13以上と、デスクトップ版 Chrome または Edge を推奨します。既定は WebGL2 で描画します。WebGPU は `?render.preferWebGPU=true` で選べます（使えない環境では WebGL2 に戻ります）。

```sh
cd game
npm ci
npm run dev          # http://127.0.0.1:5190/
```

ビルド済みの版で確認する場合：

```sh
npm run build && npm run preview   # http://127.0.0.1:4173/
```

1. ローディング画面の読み込みバーが 100% になるのを待ちます。レベル、KTX2 テクスチャ、ライトマップ、反射キャプチャ、音声、敵のモデルを約 380MB 読み込みます。
2. タイトル画面(原作のメインメニュー風)の `NEW GAME` をクリックすると、マウスが固定されて開始します。操作は下の「操作」の表のとおりです（ゲーム内に操作の一覧はありません。使えるものや壊せるものを見ると、画面の中央に手のマークが出ます）。
3. セーブがある場合は `RESUME` で続きから始めます。`NEW GAME` を押すと原作と同じく `RESTART?` の確認が出て、`YES` でセーブを消して最初から始め直します(`NO` でメニューに戻ります)。

`npm test` は規則・セーブ・設定上書き・敵の経路探索と行動・ギミックの時間と当たり・モデルのユニットテスト、`npm run typecheck` は型チェックです。

## 敵

地上の迷路には、ワサミの姿の敵が10体います（ファンゲームのマネキンの出現点 `Spawn_Enemies` の位置）。動きは原作の Murder Monkeys に倣っています（ファンゲームのマネキンの動き〈近くで速く動くと正体を現して叫ぶ、閉じた扉を通り抜ける、車に轢かれて死ぬ〉とは違います）。

- ホームにいる間は出てきません。広間のトリガーを踏むと保存され、1秒後に放たれて廊下を巡回し始めます。ときどき「おーい。」などと呼びかけ、重い足音で近づいてきます。足音と声は、敵のいる方向から聞こえます。
- 近く（壁越しでも14m、ダッシュ中は足音で約20m）にいるか、正面の視界（32m）に入ると見つかります。「ここか！」の声とともに、最短経路で追ってきます。追われている間は曲が `CC_Carol_Of_the_bells` から `CC_Merry_Dethsmass` に変わり（切り替わるたびに曲の頭から）、迷路の街灯48灯が一斉に点滅します（ファンゲームの `Lamp_zone_1` の曲線）。駅の中は無音で、曲はホールに出てから鳴り、シャードを全部集めると消えます。脱出では `CC_Merry_horrors` が鳴ります。
- 敵は歩きより速く、ダッシュより遅い（巡回 2m/s・追跡 4.3m/s。原作の `BP_Monkey` の値）ので、ダッシュすれば逃げ切れます。視線と距離を切って5秒たつと見失い、最後に見た場所を探しに行きます。
- 振り向くのが苦手です。追跡中に急に向きを変えると、0.75秒ほど止まって震えます（グリッチ）。挟まれたら、テレポーテーションで敵の背後へ抜けると逃げられます。
- 3体目ごとに、こちらの行く先へ先回りしてきます。扉は敵を止めません（ファンゲームのマネキンと同じ）。閉じたシャッターには近づくと開けます。
- 捕まると、敵が顔の前へ詰め寄った3.5秒後に死亡画面（原作と同じ REMAINING LIVES と残りのドクロ、ヒント）になり、ライフが残っていれば集めたシャードを保ったまま最後のチェックポイントに戻ります（敵も元の位置に戻ります）。ライフが0になると YOU ARE DEAD の画面で、RESTART（最初から）/ LAST CHECKPOINT（最後のセーブから、ライフ3つ）/ QUIT TO TITLE を選べます。
- 罠の扉が壊れると奥から1体、脱出では群れが現れ、出た瞬間からまっすぐ追ってきます（4.25m/s。原作の `BP_MonkeySpecial2` の 425cm/s。プールは20体）。

## ステージのギミック

どれもファンゲームの Blueprint の値（書き出しの生バイトコードで照合したもの。`.claude/references/chaotic-customer-2/README.md`）に倣っています。駅の柵・板張りの通り道とロックピック・ダッシュの障壁は、本家に無いギミックを簡単にする本作の方針で、原作の Hotel の板張りのバリケード（`BP_01_Woodboards`）の壊れ方と値に倣っています（見ると手のマークが出て、左クリック1回で壊れる）。

| ギミック | 動き |
| --- | --- |
| 駅の柵（5基） | ホームの木の柵（`Fence_battle` / `Fence_battle_2`）。区画は2つずつ（板4枚ずつ）で、2m 以内で見ると手のマークが出て、左クリック1回で区画ごと壊れる（敵が触れても壊れる）。板は物理で飛び散って体をすり抜け、原作の板の割れる音（`Wooden_Boards_Breaking_v5`）と煙（`P_Explosion1`）が出て、2秒後から2秒かけて薄れて消える。チェックポイントからやり直すと元に戻る |
| 駅の板張りの通り道（2か所） | ホームの出口に打ち付けた板（`Fence9_83`・`Fence10`〜`12`。奥にダッシュの障壁）と、ホームの低い戸口に掛かる格子の壁（`Fencing_Cube_77`）。ファンゲームはしゃがむかスライディングでくぐらせるが、本作にしゃがみは無いので、柵と同じく2m 以内で見て左クリック1回（か敵の接触）でまるごと壊れる。打ち付けた板はその場で少し下がって傾き、割れる音と煙が出て、2秒後から2秒かけて薄れて消える。チェックポイントからやり直すと元に戻る |
| ロックピックの障壁（7基） | 光る障壁。2m 以内で見ると手のマークが出て、左クリック1回で割れる（敵が触れても割れる）。灯とループの音が消え、割れる音（ファンゲームの `Barrier_Shatter_Cue`）と煙（`P_Explosion1`）が出てすぐ通れるようになり、2秒後から2秒かけて薄れて消える（板ではないので、柵のように崩れ落ちはしない）。チェックポイントからやり直すと元に戻る |
| ダッシュの障壁（4基） | ロックピックの障壁と同じく、見て左クリック1回（か敵の接触）で割れて薄れて消える。チェックポイント2以上のリスポーンから50m以内のものは最初から無い |
| シャードの障壁（2基） | ホームから来ると見えず通れ、階段を上りきった所の箱に初めて入ると現れて（音）帰り道を塞ぐ。広間から始めると最初から立っている。全回収で割れて3秒後に消える |
| 扉（210基） | 施錠121（鳴るだけ）、開き戸6（蝶番で ±91°）、通気口13（跳ね上がり、開いている間は通れる）、シャッター20（脇のボタンで巻き上がる）、ブロッカー25（腕が上がって見えない壁が消える）。動く部品は原作の支点とキーのまま動き、当たりも一緒に動く |
| 罠の扉（25基） | 手前の床に乗るたびに1/4で倒れ（最初の4回のどれかで必ず）、灯が消えて奥から敵が出る。シャードが残っている間だけ |
| 床の噴出（6基） | 前に立つと3秒噴き（煙）、4秒休む。噴いている間に入ると死ぬ |
| 車（2台） | 迷路を横切る道を27.5m/sで走り、7秒ごとに最初から。走り出すたびに色が変わる（灰・青・黒・赤）。轢かれると死ぬ。敵は10秒止まる |
| 街灯の点滅・レトロな灯 | 追跡の間は街灯48灯が一斉に点滅し、追跡が終わると暗くなってから戻る。レトロな灯7灯は同じ位相で点滅。脱出では街灯が消えて1.5秒後に色が巡回する光で点き直る。灯の変化は床の光（焼き込み）にも出る（近い3灯） |
| 脱出（チェックポイント4） | 開始の0.8秒は動けず、背後から最初のトラック（Spline_3、8秒）が走り出し、ゾーンの見えない壁が立ち、群れ15体が追ってくる。ゾーンの箱に入るたびに別のトラック（Spline_1・4・5・6）や群れ3・2体が来る。トラックは車体に触れると死に、ブームの点で止まり、行く手のシャッターを壊す。群れも行く手のシャッターとブロッカーを壊す |

## 設定（config.ts）

調整値は `src/config.ts` にまとめています。ブラー強度、FOV、ライト数、影の解像度、ブルーム、露出などです。

さらに URL クエリで、コードを変えずに任意の値を上書きできます。上書きした内容はコンソールに表示されます。

```text
http://127.0.0.1:5190/?post.motionBlur.strength=0.6&camera.fovSprint=100
http://127.0.0.1:5190/?lights.shadowCasters=2&lights.shadowMapSize=256
http://127.0.0.1:5190/?render.preferWebGPU=true           # WebGPU で描画（既定は WebGL2）
http://127.0.0.1:5190/?lights.mode=baked                   # 灯をライトマップだけで描く（比較用）
http://127.0.0.1:5190/?render.hardwareScaling=1.25         # 80% 解像度で描画
http://127.0.0.1:5190/?debug.stats=true&debug.chase=true
http://127.0.0.1:5190/?debug.traps=false                   # 床の噴出と車を止める（検証用）
http://127.0.0.1:5190/?debug.field=true                    # ステージの代わりにデバッグフィールドを読み込む
```

`debug.field=true` で開くと、ステージの代わりに検証用の広場（デバッグフィールド）を読み込みます。広場は `src/world/debug-field.ts` がコードで組み立て、ステージとそのテクスチャは読みません。48 m 四方の床に 1 m ごとの格子線（5 m ごとに太線）があり、テレポートやダッシュの距離を読み取れます。置いてあるものは、独立した壁、膝の高さの壁、2 m 幅の廊下、柱、部屋、シャード 12 個、門と出口、敵 3 体です。セーブはステージとは別のキーに保存します。敵を出さずに演出だけを確かめるときは `&enemy.enabled=false` を足します。

## アセットの作り方

生成済みのファイルは同梱しています。作り直す場合だけ実行してください。

ファンゲームの書き出し（`cc2_reference/`、git の対象外）と原作のデータ（`pak_reference/`、同じく対象外）がローカルにあることが前提です。`assets-src/level/level.glb`（約160MB）は GitHub の 1 ファイルの上限を超えるので git の対象外で、組み立てで作り直します。

```sh
npm run assets:cc2-layout    # Zone_1 の配置・灯・キャプチャ・マテリアル・ステージの目印を前処理（Blender の Python で約10秒）→ assets-src/cc2/layout.json、assets-src/level/stage.json
npm run assets:cc2-tex       # 使うマテリアルのテクスチャを UASTC KTX2 に変換し、マテリアル表を作る（人物の絵はワサミの絵に差し替え）→ public/assets/cc2/tex
npm run assets:cc2-luts      # ボリュームのカラーグレーディング LUT を実行時のデータに → src/render/stage-luts.ts
npm run assets:cc2-bake      # Blender 5.1 でステージを組み立て、ライトマップを Cycles でベイク（約80分。--no-bake で組み立てだけ）→ assets-src/level
npm run assets:cc2-colliders # UE の当たりの形から衝突の格子と階段の坂を作る → assets-src/level/colliders.json
npm run assets:ktx2          # basisu（brew install basis_universal）でライトマップのページを UASTC KTX2 に変換
npm run assets:level         # glTF にマテリアル表の KTX2 を割り当て、読み込み用 manifest を生成
npm run assets:vendor        # KTX2 デコーダと変換用 wasm を public/vendor にコピー（実行時に CDN を使わない）
npm run assets:sfx           # 効果音パックから使用分をコピーし、ステージの音を書き出しの wav から Ogg Opus に（ffmpeg）
npm run assets:shard         # models/wasami_mochi.glb を 6000 三角形に簡略化して public/assets/models へ（続けて assets:level で manifest を更新）
npm run assets:enemy         # legacy/models/wasami-enemy.glb（以前の版の敵）のテクスチャを縮め、腰の水平移動を除いて public/assets/models へ（続けて assets:level）
```

## 素材とライセンス

### ステージ

- **ステージのメッシュ・テクスチャ・配置・灯**（`public/assets/level/`、`public/assets/cc2/tex/`）：ファンゲーム『Chaotic Customer 2』の Zone_1 のものを、その書き出し（`cc2_reference/`）から変換して使っています。KTX2 のテクスチャは283枚・約235MBです。人物の描かれたポスターと落書き7種は、人物の部分をワサミの絵（`public/wasami.webp`）に差し替えています。ファンゲームのキャラクター（マネキン）は使っていません。

### その他

- **効果音・BGM**（`public/sfx/`）：Dark Deception のファンゲーム向け音源パック（Glowstick Entertainment）から使用しています。ファンゲームでの利用は許可されています。元ファイルとの対応は `public/sfx/manifest.json` にあります。
- **ステージの曲と効果音**（`public/sfx/cc2_*.ogg`）：ファンゲーム『Chaotic Customer 2』の書き出しの wav を Ogg Opus にしたもの（曲、障壁、扉、罠、トラック、配電盤、シャード）。鳴らし方（音量・ピッチ・距離による減衰）もファンゲームの値に合わせています。マネキンの声や足音は使っていません（敵はワサミなので、敵の音は効果音パックのまま）。
- **ボイス**（`public/voices/`）：以前の版から引き継いだわさみの音声です。字幕付きです。敵の呼びかけにも使っています。
- **敵のモデル**（`public/assets/models/wasami_enemy.glb`）：以前の版の敵（Meshy で作ったわさみ、待機・歩き・走りなどのアニメ付き）を軽量化したものです。
- **KTX2 デコーダ**（`public/vendor/ktx2/`）：Babylon.js の Apache-2.0 版を同梱しています。

## FPS 計測（1080p）

このステージ（Chaotic Customer 2 の Zone_1）のホールで計測した値です（2026-09-14）。経路は、チェックポイント 2 のリスポーンから、敵の格子で最も長く真っすぐ歩ける向きへ歩くものです。読み込みはどのシナリオも約17〜21秒でした。

| シナリオ | API | 平均 | p95 | 1% low | CPU |
| --- | --- | --- | --- | --- | --- |
| 全部入り（既定） | WebGL2 | 110.5 fps（9.05 ms） | 14.8 ms | 58.5 fps | 6.72 ms |
| SSR なし | WebGL2 | 109.0 fps（9.17 ms） | 15.0 ms | 56.2 fps | 6.71 ms |
| SSAO・DOF なし | WebGL2 | 110.3 fps（9.07 ms） | 14.8 ms | 57.1 fps | 6.71 ms |
| 反射キャプチャなし | WebGL2 | 111.5 fps（8.97 ms） | 14.4 ms | 59.2 fps | 6.73 ms |
| 全部入り | WebGPU | 83.4 fps（12.00 ms） | 23.6 ms | 36.0 fps | 7.38 ms |
| TAA なし | WebGPU | 93.2 fps（10.73 ms） | 19.8 ms | 41.7 fps | 7.52 ms |
| モーションブラーなし | WebGPU | 79.0 fps（12.67 ms） | 24.6 ms | 34.4 fps | 7.51 ms |
| 影なし | WebGPU | 100.4 fps（9.96 ms） | 20.1 ms | 43.9 fps | 5.89 ms |
| 内部解像度80%（1536×864） | WebGPU | 83.4 fps（11.98 ms） | 23.7 ms | 35.8 fps | 8.23 ms |
| SSR なし | WebGPU | 87.3 fps（11.45 ms） | 21.0 ms | 34.8 fps | 7.45 ms |
| SSAO・DOF なし | WebGPU | 85.8 fps（11.66 ms） | 23.3 ms | 36.8 fps | 8.23 ms |
| 反射キャプチャなし | WebGPU | 84.6 fps（11.81 ms） | 23.3 ms | 35.7 fps | 7.34 ms |

既定の WebGL2 は平均で 60fps の約1.8倍の余力があり、1% low もほぼ 60fps です。WebGPU はどのシナリオでも WebGL2 より遅く、1% low は 35〜44fps でした。数%以内の差は計測のばらつきの範囲です（モーションブラーを切った方がわずかに遅いのもそのため）。

- **計測環境**：Apple M4 Pro（16コア GPU）、macOS、Chrome（ヘッドレス、Playwright から起動）。
- **条件**：ビューポート 1920×1080、DPR 1。垂直同期とフレーム上限を切り、60fps に対する余力を測っている。
- **再現方法**：`npm run build && npm run bench` を実行する。結果は `bench-results/results.json` に保存される。

**性能の低い GPU で60fps に届かない場合の対策**（どれもコードを変えずに URL クエリか `config.ts` で切り替えられる）
1. `render.hardwareScaling=1.25` で内部解像度を80%に下げる。TAA がエッジを補う。
2. `post.motionBlur.samples=16` にするか `post.taa.enabled=false` にする。
3. `lights.shadowCasters=2`、`lights.shadowMapSize=256` にする。
4. `lights.mode=baked` にして、灯をライトマップだけで描く。

## 既知の課題

- **ダウンロード量**：ステージのジオメトリ（約122MB）、テクスチャ269枚（約241MB）、ライトマップ（4096²の2ページ、約21MB）、音（約15MB）などで約384MiB（403MB）ある。ローカルでは十数秒で読み込めるが、回線の遅い環境では、HTTP の Range 読み込みでミップを段階的に読む仕組みなどが要る。
- **露出**：地上はボリュームの物理カメラの値（ISO・シャッター・f値）から UE5 の手動露出を求め、露出補正は UE5 の既定の 1 と見なしている。ファンゲームの実際の画面との比較はしていない。
- **作っていないもの**：脱出のボス戦のマネキン（Box17。プレイヤーが殴って倒す）、トラックの標識のデカール・火・灯、脱出のゾーンの灯と飾りのマネキン、壊れた扉の破片と煙、車輪の回転。敵の動きはファンゲームのマネキンではなく原作の Murder Monkeys のもの。
- **灯の状態と焼き込み**：点滅や消灯が床の光に出るのは、プレイヤーに近い3灯だけ（それより遠い灯は発光面だけが変わる）。
- **敵**：影を落としません。物理の体も持たないので体はすり抜けられますが、中心から0.95m以内に入ると捕まります。壁越しの気配（14m）は直線距離で判定するため、厚い壁の向こうでも気づかれることがあります。
- **WebGPU の速度バッファ**：Babylon.js 9.26 では、WebGPU で PrePass の速度テクスチャが割り当てられない。WebGPU ではモーションブラーは `GeometryBufferRenderer` から速度を取得し、TAA は再投影なしでカメラが止まっている間だけ蓄積する。WebGL2 では、PrePass による再投影付き TAA がそのまま動く。
- **ライトマップ**：8bit にガンマ補正と倍率を掛けて KTX2（UASTC、リニア）に格納している。暗部の階調は EXR より粗く、ごく暗い面にバンディングが出る場合がある。
- **ライトマップの適用方法**：Babylon の PBR シェーダーは、通常のライトマップを最終色に加算するだけで、アルベドを掛けない。そのままでは白飛びするため、影なし・強度0の「キャリア」ライト（`LIGHTMAP_SHADOWSONLY`）を1灯置き、照度ライトマップを拡散項に1回だけ入れている（`src/world/level.ts`）。
- **音声形式**：効果音パックは Ogg Vorbis、ステージの音は Ogg Opus。Chrome、Edge、Firefox では再生できるが、古い Safari は非対応。
- **ブラウザでの手動確認**：Pointer Lock の実際の操作感は、Playwright ではマウス固定なしの疑似入力でしか確認していない。
