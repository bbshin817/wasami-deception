## 決定事項

- 2026-09-16 20:10: **ステージ本体の結合メッシュ 5 個の `bCastShadowAsTwoSided: True` を取り込む**（`KEEP_COMPONENT_PROPS` に足す） — Stationary に直して焼き直しても床は 146（実機 57）のままだった。床の見本の点に届く灯を数えると、天井灯 1 個と **Movable の平行光源（1.5）**で、PIE で平行光源を切ると床 146 → 117・色の比が実機と同じ G≈B になった。原作の `tiles_tile_01/02/03`・`parking`・`tunnel` は `bCastShadowAsTwoSided: True` を持つが取り込んでおらず、内側を向いた片面の天井が上からの光を遮っていなかった。PIE でこの値を立てると平行光源を切った絵と同じになった。さらにその状態で焼き込みを切ると、エレベーターの壁 (45, 59)・右の壁 36 が実機 (44, 59)・32 とほぼ一致したので、**残りの差は焼き込み（隣の部屋の灯が片面の壁・天井を抜ける）**と見て、この値を入れて焼き直す。Mobility の修正は原作どおりにするものなので残す。
- 2026-09-16 19:50: 原作のゲームの明るさ設定は効いていない — `BP_DD_GameInstance` は設定 `r.myGamma`（既定 2.2）を `gamma <値>` で入れるが、手元の本家の保存済みの設定（`%LOCALAPPDATA%/DDeception/Saved/Config/WindowsNoEditor/*.ini`）に値は無く、既定の 2.2 は UE の既定の表示ガンマと同じ。原作の `WorldSettings` にも Lightmass の設定の差分は無い。
- 2026-09-16 19:20: **原作の灯の大半は Static ではなく Stationary（BP の中で足した灯は Movable）**と判断し、取り込みの Mobility の既定を「UE の既定 = Static」から「その部品の土台の値」に直す — 書き出しは土台（アーキタイプ）と同じ値を省く。`APointLight`・`ASpotLight`・`ARectLight`・`ADirectionalLight` のコンストラクタは灯を Stationary にし（UE 5.8 の `Light.cpp:190`・`SpotLight.cpp:27`・`RectLight.cpp:12`・`Light.cpp:244`。UE4 から同じ）、`USkyLightComponent` も Stationary（`SkyLightComponent.cpp:312`）、`AStaticMeshActor` はメッシュを Static（`StaticMeshActor.cpp:34`）、それ以外のコンポーネントの既定は `USceneComponent` の Movable（`SceneComponent.cpp:124`）。原作の全レベルで `PointLight` アクタの灯は「省略 1,342・Movable 779・Static 193」で **Stationary と書かれたものが 1 つも無い**ので、省略は Stationary を意味する（BP の中で足した灯には Stationary 12 が明示されている）。Zone 1 で数え直すと Stationary 670・Movable 451（シャード 337 個は `BP_Shard_C` の SCS の灯で土台が `Default__PointLightComponent` = Movable。拾うと消えるので理にかなう）。**いまの本作は 1,015 個を Static として直接光まで焼いており、これが床と壁の明るさの差の最有力の原因**（PIE で焼き込みを切ると床 136 → 70・壁 69 → 14、動的な灯を切ると床 136 → 103。天井の中央だけは実機と合っている）。
- 2026-09-16 19:20: 灯の値は `scene.json` の `light` ではなく **`full.json` のコンポーネントの値**から取り、BP の灯は「クラスの既定＋レベル側の差分」にする — `scene.json` の `light` は `full.json` の一部で、Zone 1 では `SoftSourceRadius` 386 個・`LightingChannels` 6 個（カットシーンの灯。チャンネル 1 だけを照らす）・矩形灯の `SourceWidth`/`SourceHeight`・`MaxDrawDistance` が落ちていた。BP の天井灯 294 個はレベル側に `MaxDrawDistance 4000`・`MaxDistanceFadeRange 2000` を持つが、値が空なので使っていなかった。`MaxDrawDistance`/`MaxDistanceFadeRange` を省く設定（`SKIP_LIGHT_PROPS`）も、動的に描く灯には効くので外す。IES（救急車のスポットライト 2 個・強さ 0）は今は影響しないので扱わない。

- 2026-09-16 18:10: **色味の差の主因は `M_DD_Substance` のコンパイル失敗**と判断し、計画を「失敗を直す → 焼き直す → 残りを切り分ける」に変えた — 実機の開始地点の絵と本作の `zone1-start-pie-baked.png` を並べると、本作は壁も床も灰色の市松（`DefaultMaterial`）で、金属の壁・床の赤い帯が出ていなかった。ログには `Failed to compile Material Instance with Base M_DD_Substance for platform PCD3D_SM6, Default Material will be used in game.` が 814 件あり、理由は全件 `(Node TextureSampleParameter2D) Sampler type is Linear Color, should be Masks for /Game/Pipeline/Textures/T_DD_DefaultPacked`。グラフは Packed を `SAMPLERTYPE_LINEAR_COLOR` で作るのに、既定テクスチャだけ `TC_Masks` で取り込んでいた（どちらも最初の取り込みのコミット `b2c4333` から）。焼く前の Lumen の絵（`zone1-start-pie.png`・`zone1-corridor-pie*.png`）にも市松が出ているので、これまでの色の比較はすべてこの状態のもの。Lightmass も既定のマテリアルを反射率に使って焼いたはずなので、直したら焼き直す。
- 2026-09-16 18:24: **灯の色（FColor）は書き出しの配列が [B, G, R, A] の順**と判断し、取り込みで並べ替える — エンジンは FColor を `Ar << Color.DWColor()`（uint32、リトルエンディアンでメモリの並び B,G,R,A。`Engine/Source/Runtime/Core/Public/Math/Color.h:547,577`）で書き、書き出しの道具は `pak_reference_2/_tools/scripts/ue4.py:255` の `'Color': ('u8', 4)` でファイル上の順のまま出している（`pak_reference` の道具も同じ）。同梱の CUE4Parse の `FColor` も B,G,R,A の並び。見え方も一致する: 天井灯 294 個の [255, 251, 200] を B,G,R と読むと (200, 251, 255) の青白い光で、実機の開始地点の床 (47, 61, 61) の R/G 0.77・G≈B と合う（本作の黄色い床 (156, 144, 114) は B/G 0.79 で、ちょうど逆）。扉枠の灯 234 個の [74, 57, 255] は (255, 57, 74) の赤で、実機の廊下 `ref-zone1-corridor-01-full.png` で扉枠の上が赤く光っているのと合う（本作では青く光っていた）。辞書の形（{"R","G","B"}）の色は名前つきなので並べ替えない。
