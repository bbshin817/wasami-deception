# 中断した実装の続きを始める

`.claude/guides/progress-tracking.md` の「再開の手順」を実行する形にしたもの。**記録と git とエディタの状態だけから再開する**（前のセッションの会話は残っていない前提で進める）。

セッション開始時の hook（`.claude/scripts/session_start_hook.py`）が、未完了の進捗記録・main 以外のブランチ・未コミットの変更・直前のコミットを既に知らせている。その内容を出発点にする。

**無人モード**（環境変数 `WASAMI_UNATTENDED=1`。hook が「無人モード」と知らせる）のときは `.claude/guides/autonomy.md` に従う: 質問せず（`AskUserQuestion` は使わない）、仮の値で進めて記録の「要確認（ユーザー）」に書き、ステップを終えたら `/clear` を頼まずに状態ファイルを書いて応答を終える。バックグラウンドの作業（サブエージェント・`run_in_background` のコマンド）を残したまま応答を終えない。

**有人セッション**（無人モードの合図が無い）では、このスキルはユーザーに頼まれたときと、有人の作業の途中で `/clear`・圧縮が入ったときだけ使う（2026-09-18 から、作業一覧を進めるのは基本、無人運転。有人セッションの始め方は `.claude/guides/autonomy.md` の「有人セッション」）。hook が「駆動役が動いています」と知らせたら、変更の前にユーザーに止めてもらう。

## 1. どこから再開するかを決める

```bash
ls .claude/progress/          # _template.md 以外があれば、それが未完了の作業
git branch                    # main 以外のローカルブランチも未完了の大規模改修かもしれない
git status --short
```

- **未完了の進捗記録がある** → その記録を読む。これが正本。
- **記録が無く（`status: 保留` の記録だけのときも同じ）、main 以外のブランチもない** → 前の実装は完了している。作業一覧 `.claude/roadmap.md` の**進行中の大目標の節**で「未着手」かつ依存が満たされた最初の項目か、作業一覧が無ければ `.claude/references/handover.md` の「現状と次の一歩」の 1 番目から始める。**新しい作業なので、まず進捗記録を作る**（`.claude/progress/_template.md` を写す。ファイル名は `<YYYYMMDD>-<slug>.md`）。無人モードでは、この最初の反復は計画（記録の作成とコミット）だけで終える。
  - **大目標を超えない**（`.claude/guides/autonomy.md` の「何を作業するか」）: ほかの大目標の節の項目は始めない。進行中の大目標の項目がすべて完了しているのに大目標が「達成」になっていなければ「達成（日付）」にしてコミットし、進行中の大目標が無ければ何も始めない。どちらも無人モードでは `stop` を書いて終える（人がいるときは報告して指示を待つ）。**ただし次の大目標の節の頭の `- 始め方:` が「自動」なら**（いまは大目標 2。2026-09-19 のユーザーの指示）、止まらずに前の大目標を「達成（日付）」・次の大目標を「進行中（日付から）」にしてコミットし（その大目標の項目の `status: 保留` の記録は `進行中` に戻す）、その節の最初の項目から始める。
- **記録が複数ある** → 無人モードでは `status: ユーザー待ち` と `status: 保留` の記録を飛ばし、残りをファイル名の順（古い順）に扱う。人がいるときは、どれを進めるかをユーザーに確かめる。
- **記録は無いのに main 以外のブランチや未コミットの変更がある** → 記録されていない作業。ユーザーの手による変更かもしれないので**触らずに確認する**。

読む順は「進捗記録 → 記録が名指しする実装記録（`.claude/implementation-records/`）→ handover」。**hook が「上限 30 KB を超えています」と知らせた記録は、ステップに進む前に全体を畳んで 1 コミットにする**（それを 1 ステップと数える）。ガイド（`.claude/guides/`）は必要になった節だけを読む。コンテキストを使い切らないよう、関係しないゾーン・記録は読まない。

## 2. 記録と実際の状態を照合する

記録の `base`（開始時の HEAD）と計画のチェックボックスが、実際の git とアセットに合っているかを確かめる。

```bash
git log --oneline <base>..HEAD      # 記録の base から何が入ったか
git status --short
git log -1 --format=%cr             # 直前のコミットからの経過（push の判断に使う）
git status -sb                      # ahead N = 未 push の件数
```

エディタ側は、記録の「再開時の注意」に書かれた出力（取り込んだアセット、組み立てたレベル、走らせたままの処理）を実際に確かめる。

```bash
python Tools/ue_remote.py -c "
import unreal
def main():
    print('level:', unreal.get_editor_subsystem(unreal.UnrealEditorSubsystem).get_editor_world().get_name())
    print('in PIE:', unreal.get_editor_subsystem(unreal.LevelEditorSubsystem).is_in_play_in_editor())
    print('dirty:', [p.get_name() for p in unreal.EditorLoadingAndSavingUtils.get_dirty_map_packages()])
main()
"
```

**食い違いを見つけたら、git・実ファイル・アセットの実際の状態を正として記録を直す。** どちらが正しいか決められないときはユーザーに確認する（無人モードでは捨てずにそのまま残し、要確認に書いて、触らずに進められるステップへ）。**変更を捨てる操作（`git checkout --` / `restore` / `reset --hard` / `stash`、アセットの削除）は、必ず先にユーザーの確認を取る**（無人モードでは行わない）。

## 3. ベースラインを確かめる

- **エディタが起動して応答するか**: 上の `ue_remote.py` が答えれば起きている。答えなければ `tasklist | grep -i UnrealEditor` で確認し、起動していなければ `python Tools/editor_cycle.py`（Claude は Windows のセッション 0 にいるので `UnrealEditor.exe` を直接起動しても落ちる）。エディタを閉じる・開き直すのに確認は要らない（`.claude/guides/verification.md`。閉じる前に保存する）。
- **PIE が残っていたら止める**（`editor_request_end_play`）。残っているとアセットの操作が `The Editor is currently in a play mode.` で失敗する。
- **MCP が応答しないとき**は `Tools/ue_remote.py` で作業できる（この PC は Docker Desktop が 127.0.0.1:8000 を掴むため、エディタを開き直すと MCP の接続が切れる。`/mcp` で再接続する）。
- **C++ を変える作業なら**、ビルドが通る状態から始める（`python Tools/editor_cycle.py`）。

## 4. ステップを 1 つ実行する

進捗記録の「計画」から、**未完了のステップを 1 つだけ**取る。1 ステップは 1 コミットで終わる大きさ。

1. そのステップを記録で「作業中」にし、**変更する予定のファイルとアセット**（`/Game/...`）を書く。
2. 実装する。時間のかかる処理（取り込み、レベルの組み立て、ライティングのビルド、シェーダーのコンパイル、C++ のビルド）は**先に「再開時の注意」へ、実行する手順・出力先・完了の確かめ方を書いてから**走らせる。バックグラウンドで走らせ、待つ間に別の作業を進める。**ただし応答を終える前に、必ず終わりを待って結果を読む。** 調査などのサブエージェントは前面（`run_in_background: false`）で呼ぶ。無人モードでバックグラウンドの作業を残して応答を終えると、`claude -p` が 600 秒で打ち切り、その反復の成果が失われる（`.claude/guides/autonomy.md` の「無人モード」）。
3. 判断したこと・ユーザーに確認して決めたことは、その場で「決定事項」に理由つきで書く。
4. 検証する（`.claude/guides/verification.md`。PIE・エディタの開き直し・本家の起動に確認は要らない。PIE は終わったら必ず止める）。
5. ソースを変えたなら対応する実装記録を直し、`python .claude/scripts/check_records.py --update` を通す。
6. 記録のステップを完了にし、**そのステップの分を畳み**（`.claude/guides/progress-tracking.md` の「記録を畳む」: 完了したステップは 1〜2 行、決定事項は残りのステップに効くものだけ〈実装済みのことの理由は実装記録へ移してから消す〉、再開時の注意と検証は今も効くものだけ）、「次にやること」を次のステップに置き換えてから、**記録も一緒にコミットする**。
7. push の条件（未 push 2 件以上 / 最終コミットから 10 分以上 / 大規模改修のマージ後）を満たしていれば main を push する。

## 5. ステップが終わったら

- **まだ残りのステップがある** → ここまでを記録に残し、**ユーザーに `/clear` をお願いする**（何が終わったか・次に何をするか・再開のために読むファイルを 1〜3 行添える）。会話が長いほど精度が落ちるので、続きは新しいセッションで始める。
- **作業がすべて終わった** → 実装記録と `handover.md` の「現状と次の一歩」を直し、**進捗記録を削除して**最後のコミットに含める（経緯は git 履歴に残る）。そのうえで `/clear` をお願いする。
  - **その項目で進行中の大目標の項目がすべて完了になった**ら、同じコミットで `.claude/roadmap.md` の大目標の `- 状態:` を「達成（日付）」にし、handover の「現状と次の一歩」にユーザーが遊んで確かめる手順を書く。無人モードでは状態ファイルを `stop`（理由「大目標 N（名前）を達成」）にする。**次の大目標の始め方が「自動」なら**、同じコミットで次の大目標を「進行中（日付から）」にし、状態ファイルは `continue`（`done` に「大目標 N を達成し、大目標 N+1 へ移った」）にする（次の反復がその節の最初の項目から始める）。
- **無人モード**では `/clear` を頼まない。コミットまで終えたら `Intermediate/Overnight/status.json` に `{"result": "continue" | "stop", "reason": ..., "step": ..., "commit": ..., "written": ..., "done": ..., "summary": [...], "learned": [...], "pending": [...], "shots": {"caption": ..., "files": [...]}}` を書き（`.claude/guides/autonomy.md` の「セッションの終え方」。`done` はこの反復でしたことの 1 行で、終わりのまとめの「やったこと」に並ぶ。後ろの 4 つは Discord の反復の報告の作業概要・分かったこと・要検討事項・スクショになる。**`pending` はこの反復で新しく要確認に書いたものだけ**、`shots` は人に見せる画像だけ〈特殊効果・敵の動き・シャードの回収などの連番のグリッド。10 枚まで。確かめるために撮ったもの・エディタの調整・デスクトップ全体・本家の絵は付けない。無ければ省く〉。書き方は同じガイドの「Discord への通知」）、何が終わったか・次に何をするか・要確認の件数を 1〜3 行書いて応答を終える。駆動役が次の反復を始める。

## 迷ったら

| 状況 | どうするか |
| --- | --- |
| 記録の計画が今の状況に合わない | 計画を書き換え、理由を「決定事項」に書く。大きく変わるならユーザーに確認する |
| ステップが 1 コミットに収まらないと分かった | その場でステップを分け直して記録に書く |
| 記録に無いファイル・アセットの変更がある | ユーザーの作業かもしれないので触らず、報告して確認する |
| 中間状態が残る処理の途中で止まっていた | 「再開時の注意」の完了の確かめ方で今どこまで進んだかを判定してから、続きか、やり直しかを決める |
| 無人モードで、値や作りを決められない | `.claude/guides/autonomy.md` の「決め方」の階段（本家のコード → 実機 → WebGL 版 → 仮の値）。ゲームの規則の値が本家のコードに無ければそのステップを「ユーザー待ち」にして次へ、無ければ `stop` |
| 大目標 1・2 で、見た目を本家に合わせたくなった | 合わせない。原作のアセットをそのまま使い、無いもの・式が消えたものは手早い推定で済ませ、作業一覧の項目 28 の「後回しの一覧」に 1 行書く（`.claude/roadmap.md` の「大目標 1・2 の決め方」） |
| 無人モードで、同じ失敗の修正が 2 回とも駄目だった | 症状索引（`.claude/references/troubleshooting.md`）に「未解決」で書き、ステップを飛ばすか `stop` |
