## 原作データの調べ方

- 最初に `pak_reference/README.md` と `_manifest.json` で、どこに何があるかを確かめる（Blueprint のバイトコード `_bytecode/`、全アセットのプロパティ `_assets/`、カメラ `_camera/`、SoundCue `_soundcues.json`、マテリアル `_materials.json`、パーティクル `_particles.json`、レベル配置 `_levels/`、音 `.ogg`、テクスチャ `.png` など）。
- 大きい JSON は全体を会話に読み込まず、スクリプトで必要な部分だけ抜き出す。
- Blueprint の処理はバイトコードの実行経路（イベント入口 → 分岐 → 呼び出し）をたどり、呼び出しのリテラル引数まで確かめる。再生時の値は、呼び出し側の引数と参照先アセット自身の設定の両方で決まることがあるので、両方を見る。
- 本家の座標は UE の cm・Z 上のまま使える（WebGL 版のような座標変換は要らない）。`_levels/*.scene.json` の `world` はアタッチ階層を合成済みの絶対変換。
- `pak_reference_2` のメッシュは CUE4Parse の glTF（`_meshes_gltf/**.gltf` + `.bin`、LOD0 のみ、UV 8 組、頂点色つき、マテリアル名はスロット名）。`pak_reference` の umodel 版とは書き出し器が違う。
- WebGL 版の記録（`<WEBGL>/.claude/implementation-records/`）には、原作データのどこから値を取ったか（アセット名・関数名・バイトコードのオフセット `@1234`）が書いてある。同じ要素を作るときは、まずそこを引く。

## 原作データで確定できないとき

cook で消えた情報（ベイク済みライティング、動画、エディタ上の設定）や、実行時にしか決まらない見え方・手触りは、原作データだけでは確定できない。推測で埋めずに次の順で進める（**大目標 1・2 の間の見た目は、この手順を使わず上の「大目標による違い」のとおり推定で済ませる**）。

**材質の式は推定しない**: `_assets/**.json` の `Expressions` がほとんど null でも、最新版の `.uexp` にはコンパイル済みのシェーダー（zlib で包んだ DXBC）が残っていて、`python Tools/dd/cooked_shaders.py "<pak のパスの一部>."` で逆アセンブルすると式・定数・パンの速さがそのまま読める（2026-09-18。読み方は `.claude/implementation-records/01-stage-pipeline.md` の「cook のシェーダーを読む」）。推定の材質を作る・直す前に、まずこれで読む。収録との見比べは、読んだ式を写した後の確かめに使う。

1. **切り分ける**: 原作データから確定できる範囲を先に確かめ、確定できない部分を具体的に絞り込む。
2. **観察する**: 手元の参考映像や、これまでに受け取った収録で観察する。足りなければ、上の「本家のゲームを手元で動かす」に従って**実機で観察する**（その場面がこのビルドで出せるかを先に確かめる）。
3. **収録を求める**: 観察に足る映像がなく、実機でも出せない場面（チャプター 5 など）のときは、ユーザーに本家の画面収録を依頼する（確かめたいこと、再現の手順、撮り方〈60fps・解像度・音声・UI の有無〉を書く）。
4. **測る**: 収録をコマ単位で見て、時間・大きさ・色・動きを測る。本作の同じ場面を同じ条件で撮り、並べて比べる。
5. **検討して決める**: 候補が複数あって見た目や手触りを大きく左右するときは、候補と根拠を示してユーザーに確認する。無人モード（`.claude/guides/autonomy.md`）では、見た目なら仮の値で進めて候補と根拠を記録の「要確認（ユーザー）」に書き、ゲームの規則の値ならそのステップを「ユーザー待ち」にして次へ。
6. **記録する**: 観察から決めた値は「推定」と明記し、何から・どう推定したかを書く。

## 原作から離れるとき

- UE の版の違いなどで原作どおりにできないときは、見た目と手触りが最も近くなる代替を選び、違いと理由を記録に書く。
- ユーザーの指示が原作と違うときは、ユーザーの指示に従う。

## 原作の素材の使用範囲

| 区分 | 素材 | 扱い |
| --- | --- | --- |
| 使わない | 原作のロゴ（タイトルロゴ、開発元のロゴ、ロゴの入ったテクスチャや画像） | 本作独自のもの（`<WEBGL>/public/title/logo.webp` など）を使う |
| 使わない | キャラクターのモデル（敵・人物・プレイヤーの手や腕のスケルタルメッシュと、それに付くマテリアル・テクスチャ） | 本作独自のモデル（ワサミ）を使う |
| 使ってよい | オブジェクトとステージのモデル（建物、壁・床・天井、ドア、家具、小物、シャードなどのスタティックメッシュ）と、それに付くマテリアル・テクスチャ、レベルの配置 | 原作どおりに使う |
| 本作のものに替える（例外） | シャードの結晶（`soul_shard_skeletal`・`m_crystal_Inst1`） | 本作のワサミ餅（`SourceArt/Wasami/wasami_mochi.glb`。2026-09-17、ユーザーの回答） |

- 上の区分に当たらない素材（音、効果のテクスチャ、カメラやパーティクルの値など）は使ってよい。
- 判断に迷うもの（キャラクターのアニメーションを本作のモデルに移して使う、キャラクターが写った画像や UI 素材など）は、使う前にユーザーに確認する。
- ステージの中にキャラクターの姿が描かれたテクスチャ（ポスター、看板など）があったときは、WebGL 版で CC2 に対して行ったように、ワサミの絵に差し替えるかをユーザーに確認する。

## 原作データから素材を作るとき

- 参照データ（`pak_reference/`・`pak_reference_2/`・`cc2_reference/`）は git に入れない。素材は `Tools/` の前処理と `Content/Python/wasami_tools` の取り込みで作り、何度でも作り直せるようにする。
