## 許可の範囲

- ユーザーが許可したのは **新規記事の作成** と **記事の編集・更新** だけ。**削除はしない**（要るときはユーザーに確認する）。
- この記事の公開はユーザーが決めた（2026-09-17。スクショに原作のステージの素材が写ることを伝えたうえでの回答）。公開中の記事の書き換えは「編集・更新」なので確認は要らない。**別の記事を新しく公開するとき**は、あらためてユーザーに確認する（`tmp/note-cli/CLAUDE.md` の「公開指示がなければ勝手に公開しない」、`.claude/guides/distribution.md` の「一般公開を前提にしない」）。
- 記事に書かないもの: 原作データの取り出し方や置き場所（`pak_reference*` など）、配布やダウンロードの案内、ユーザーの個人情報、セッションの値。冒頭の「非公式のファン作品・原作のロゴとキャラクターのモデルは使わない・配布の予定はない」の断りは消さない。

## セッションの値（`_note_session_v5`）

- **置き場は `Tools/note.local.json`（git の外。`.gitignore` の `/Tools/*.local.json`）。** 形は `{"note_session_v5": "<値>", "given": "<受け取った日>"}`。
  - 2026-09-18 のユーザーの指示（「notion_session_id を失っているのが問題です。非追跡ファイルへきちんと記録してください」）で、それまでの「ファイルに書かない・会話で渡された値だけを使う」をやめた。`/clear` のたびに値を失い、note が何ステップも未反映のままになっていたため。`tmp/note-cli/CLAUDE.md`・`AGENTS.md` の「ファイルへ保存しない」より、このプロジェクトではこの指示を優先する。
  - 会話で新しい値をもらったら、その場でこのファイルを書き換える（`given` も直す）。
- **このファイルのほかには書かない**（ソース・設定・原稿・ガイド・進捗記録・ログ・コミット・メモリ・Discord への送信のどれにも）。値を画面に出さない（`cat` や `Get-Content` で表示しない）。報告やコマンドの説明では `<PROJECT_SESSION_TOKEN>` と書く。
- 使うときは、下の「コマンド」のとおり `--session` にこのファイルから実行時に読み込む。無人モードでも同じように使ってよい。
- **ファイルが無い・値が空のとき**は、原稿 `docs/note/progress.md` だけを直してコミットし、完了の報告に「note へは未反映（セッションの値が無い）」と 1 行書く。値を探したり推測したりしない。次に値をもらったときに `edit` を 1 回走らせれば追いつく。
- `401` が返ったら止めて、値の出し直しをユーザーに頼む（無人モードでは「要確認（ユーザー）」に書いて、原稿だけ直す）。無制限に再試行しない（非公式の API）。

## いつ更新するか

- **実装が 1 つ終わったとき**（進捗記録のステップをコミットした後、`/clear` をお願いする前）。作業一覧 `.claude/roadmap.md` の項目が終わったときは必ず。
- 遊ぶ人から見て何も変わらないステップ（内部の整理、記録だけの変更）では更新しない。
- 短い間に何度も投稿しない（1 ステップにつき 1 回）。

## 書き方

- **簡潔に端的に。** 読むのはゲームを遊ぶ側の人なので、クラス名・ファイル名・原作データの話は書かず、「いま何が出来るか」を書く。
- 構成は固定: 最終更新の日付 → 紹介 1 行と断り → **いま出来ること**（出来ることごとに説明 1〜2 行と GIF 1 本）→ **これから**（1〜2 行）。まだ無いもの・進み具合の一覧・更新履歴は書かない（2026-09-18 のユーザーの指示）。
- 出来ることが増えたら、節か項目と GIF を足す。見た目や操作が変わったものは GIF を撮り直す。
- 見出しは `##` と `###`（note の h2・h3 になる。`####` も h3 になるので、パワーのような並びは太字の項目で書く）。表は使わない。画像の alt は note の画面に出ないので、説明は本文に書く。
- 実際と違って見えるものは一言添える（例: 敵がまだ自分で動かないので、GIF の敵は確かめのために置いた・走らせたものだと書く。遅くして撮ったものは何分の 1 の速さかを書く）。

## GIF

2026-09-18 に 8 本撮った（`01-run-collect`・`02-tablet`・`03-speed-boost`・`04-teleport`・`05-telepathy`・`06-primal-fear`・`07-telekinesis`・`08-vanish`）。撮り直すときも同じ作り方にする。

- **撮る**: PIE を始める → `pie.py cmd "DisableAllScreenMessages" "t.MaxFPS 60"` → ビューポートを 1 回クリック（`click 2400 530 --allow UnrealEditor.exe`）→ `pie.py place` で置く → `python Tools/desktop.py record --grab gdi --region 1826 205 2978 859 --seconds 7〜10 --name note-<名前>.mkv`（すぐ返る。ビューポートの位置は `observations/tools/check_viewport.py` で確かめる）→ 約 1 秒待ってからキーを送る（`key q` / `hold shift w --ms 6000` / `scroll --dx -120` / 座標なしの `click` は今のマウスの位置で押すので視点がずれない）→ 終わったら `ffmpeg -i <mkv> -vf "fps=2,scale=288:-1,tile=4x5" -frames:v 1 <png>` のコマの一覧で中身を確かめる → 最後に `pie.py stop`。
- **パワーの枠**: Space でタブレットを出し、1 / 2 で左右の枠を回して Space でしまう（順は Speed Boost → Teleport → Telepathy → Primal Fear → Telekinesis → Vanish。PIE を始めると両方 Speed Boost）。今の枠は `observations/tools/note_gif.py` の `sockets()`。再使用までの待ち（Primal Fear は最大段階で 23 秒）は `is_power_available` で確かめる。
- **敵**: `observations/tools/note_gif.py`（`stand`・`run_to`・`use_when_near`）。敵は自分では動かないので、走らせるのは確かめ用の操作。
- **撮る順**: 02 で枠が変わるので、Q で Speed Boost を使う 03 を先に撮る。その後 2 → 1 で左 Primal Fear・右 Telepathy にすると 05（E）と 06（Q）がそのまま撮れる（2026-09-18 に 02・03・05・06 を撮り直したときの順）。
- **2026-09-18 の撮り方**: (01) 待合 (0, 350)・ヨー −90・ピッチ −6 から `hold shift w --ms 6000`。(02) (0, −2900)・ヨー 90 で Space → Z → 1 → 1 → 2（タブレットは画面の左下に小さく出るので `crop=844:474:0:180` で切り出す）。(03) (0, 1200)・ヨー −90 で Q → `hold w --ms 6000`（突き当たりの壁の前で切る）。(04) (0, 300)・ピッチ −14 で `hold w --ms 600` → Q → ホイールで 2 目盛り手前 → 1.5 秒後にクリック。(05) 敵を (−650, −2400)・(650, −1400) に立たせ、(−650, −1400)↔(−650, −1900) を `enemy_probe.shuttle` で歩かせ、プレイヤー (0, −750)・ヨー −90 で E。(06) プレイヤー (−60, −500)・ヨー −72・ピッチ −4、敵を (130, −2600) に立たせ、撮り始めて 0.8 秒後に `run_to(130, −700)` と `use_when_near(350)`。(07) PIE を始め直して餅を戻し、(0, 700)・ヨー −90 で `slomo 0.25` にして Q（一瞬で終わるので遅くする。撮ったら `slomo 1`）。(08) (0, 300) で E → `hold w --ms 4000`。餅を回収してしまう撮り方（01・03・04）の後に 07 を撮るときは、PIE を始め直す。
- **GIF にする**: 幅 640（note の本文の幅は 620 px ほど）、1 本 3〜8 秒。`ffmpeg -ss <始め> -t <長さ> -i <mkv> -vf "fps=15,scale=640:-1:flags=lanczos,split[a][b];[a]palettegen=max_colors=192:stats_mode=diff[p];[b][p]paletteuse=dither=bayer:bayer_scale=4:diff_mode=rectangle" -loop 0 observations/ours/note/gif/<番号>-<名前>.gif`。走るものなど動きの大きいものは `fps=12`・`max_colors=128` にする（それでも 5〜7 MB。2026-09-18 の 8 本で計 30 MB）。

## コマンド（プロジェクトの根から PowerShell で、必ず 1 行で）

決まりの正本は `tmp/note-cli/AGENTS.md`（note の操作の前に読む。セッションの値の置き場だけは上の節が優先）。

```console
# 公開中の記事を書き換える。セッションの値は Tools/note.local.json から読むので、コマンドの文に値は出ない
python tmp/note-cli/note_cli.py edit --session (Get-Content Tools/note.local.json -Raw | ConvertFrom-Json).note_session_v5 --id 180735989 --key n38f5d6ef4565 --title 'WASAMI DECEPTION（UE5 版）開発進捗' --body-file docs/note/progress.md --markdown --no-notify
```

- 画像の相対パスは原稿のフォルダから解決されるので、プロジェクトの根から走らせてよい。

- 投稿の前に、API を使わない変換だけを確かめられる: `markdown_to_note.convert(md, {"imageResolver": <ダミー>})` が例外を出さないこと。
- 結果の JSON の `status` を確かめ、報告には タイトル・id・key・status・editor_url だけを書く。
- 書き換えのたびにフォロワーへ通知が飛ばないよう、更新は `--no-notify`（最初の公開の通知は 2026-09-17 に済んだ）。
