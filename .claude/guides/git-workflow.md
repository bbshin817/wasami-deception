# コミットとブランチの運用ルール

WebGL 版の同名のルールを UE5 版に合わせたもの（2026-09-16 のユーザーの回答: 運用は WebGL 版と同じ、スクリプトで作り直せる素材は git の外、手作りのアセットは Git LFS）。

## 基本: 実装ごとにコミット

- 実装が 1 つ完了したら、その都度コミットする（複数の実装をまとめて 1 コミットにしない）。
- コミット前に、変更に応じて C++ のビルドと、エディタでの確認（MCP での取り込み・組み立て・PIE）を済ませる。
- 進捗記録（`.claude/progress/`）の更新は、そのステップのコミットに含める。作業が完了したら、最後のコミットで記録ファイルを削除する。
- ステージするのは今回の作業で変更したファイルだけ。作業開始前からある無関係な未コミット変更は含めない。
- コミットメッセージは既存履歴に合わせ、日本語で「何をどう変えたか」を 1 行目に書く。

## 大規模改修: 作業ブランチで進める

次のいずれかに当てはまる場合は大規模改修とみなす。

- 複数の仕組み（プレイヤー、敵、ギミック、UI、取り込みなど）にまたがる変更
- 途中の段階で main を壊す（ビルド・起動が通らない）可能性がある変更
- 複数回のコミットに分けて進める見込みの変更

手順: main から作業ブランチ（`feature/<内容>` など）を作り、実装ごとにコミットし、終わったら作業ブランチ上で進捗記録を消すコミットをして main にマージし、ローカルブランチを削除する。

## push のタイミング

次のいずれかに当てはまったら、ユーザーの指示を待たずに main を `origin` へ push する。

- 未 push のコミットがあり、最終コミットから 10 分以上経過している
- main の未 push コミットが 2 件以上になった（コミット直後に push する）
- 大規模改修が完了し、作業ブランチを main にマージした（マージ直後に push する）

補足:

- 経過時間と未 push 件数は、作業開始時と各コミットの直後に確認する（`git log -1 --format=%cr`、`git status -sb` の `ahead N`）。
- push 対象は main のみ。作業ブランチは push せず、ローカルで完結させてマージ後に削除する。
- push が拒否された（リモートが先行している）場合は force push せず、ユーザーに報告して対応を確認する。

## 素材（Content）

- 参照データ（`pak_reference/`・`pak_reference_2/`・`cc2_reference/`）と、そこからスクリプトで作り直せる素材（`/Game/CC2`・`/Game/DD`・`/Game/Pipeline`・`/Game/Stage`）は `.gitignore` で除外する。作り直す手順は `.claude/guides/unreal-workflow.md`。
- 手で作るアセット（UI のウィジェット、Blueprint など）は Git LFS で扱う（`.gitattributes` の `*.uasset` / `*.umap`）。GitHub の LFS の無料枠は 1 GB なので、大きな素材を足す前に大きさを確かめる。
- 生成するフォルダに手で作ったアセットを置かない（除外されてしまう）。
