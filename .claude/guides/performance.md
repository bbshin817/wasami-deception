# 性能とメモリの運用ルール

2026-09-16 のユーザーの指示（「パフォーマンスに関わる設定を見直し、VRAM・RAM ともに逼迫を避けながら開発を行う。ただし最終的にビルドして遊べるゲームの品質を損なってはならない」）。

## この PC

| | |
| --- | --- |
| CPU | Intel Core i7-9700K（8 コア 8 スレッド） |
| GPU | GeForce GTX 1660 SUPER、**VRAM 6 GB**（RT コアなし。ハードウェアのレイトレースは使わない） |
| RAM | 32 GB |

開発するのも遊ぶのも同じ PC。病院のステージは Zone 1 だけで配置 923・灯 1,120・テクスチャ 282 枚あり、**VRAM 6 GB はこの規模に対して小さい**。エディタは同じ素材を編集用の解像度で持つので、遊ぶときよりさらに食う。

## 大原則（この順に優先する）

1. **製品の品質は落とさない。** パッケージした本編の見た目・挙動は本家に忠実なまま保つ。フレームレートのために原作と違う絵にしてよいのは、ユーザーが決めたときだけ。
2. **逼迫を避けるのは開発中の話。** VRAM / RAM を減らすための設定は、**エディタにだけ効く場所**に置く（`Config/DefaultEditorPerProjectUserSettings.ini`、エディタのスケーラビリティ設定、コンソールコマンド、`Saved/Config/`）。`Config/DefaultEngine.ini` の描画設定など**パッケージに入るものは品質を落とす方向に変えない**。
3. 製品側の設定を落とさないと動かない・作れないと分かったときは、勝手に決めずユーザーに確認する（何が足りないか、何を落とすと絵がどう変わるか、代わりの案を添えて）。

## 開発中に守ること

- **レベルは必要な 1 つだけ開く。** `L_Hospital_Zone1` と `L_Hospital_Zone2` を同時に開かない。作業が終わったら空のレベルに移ってもよい。
- **一括の取り込みは小分けにする。** `import_dd_stage_assets(max_items)` のように `remaining` が減る形で回し、合間に保存する（`.claude/guides/unreal-workflow.md`）。
- **PIE は出しっぱなしにしない**（`.claude/guides/verification.md`）。PIE 中はエディタとゲームの両方が素材を持つ。
- **重い処理を重ねない。** 取り込み・シェーダーのコンパイル・C++ のビルド・パッケージを同時に走らせない。
- **新しく足す仕組みが毎フレーム描くもの**（シーンキャプチャ、レンダーターゲット、ポストプロセス）は、大きさと更新の頻度を決めた根拠を実装記録に書く。要らないときは止める。
- 作った素材の解像度・圧縮・LOD グループは原作の設定をそのまま使う（勝手に上げない）。

## 測り方

- PIE かパッケージで `stat unit`（フレーム時間）、`stat fps`、`stat RHI`（テクスチャプールの使用量）、`stat streaming`、`stat memory`。GPU の内訳は `ProfileGPU`。
- 目安: **1080p で 60 fps 前後**、VRAM は 6 GB に対して 5 GB 程度まで、エディタの常駐 RAM は 32 GB に対して 20 GB 程度まで。
- 測ったら、値と条件（解像度・場所・スケーラビリティ）を実装記録か進捗記録に残す。前の測定と比べられるようにする。

## 重いときに見るところ（順に）

1. **灯の影**（Zone 1 だけで 1,120 灯、仮想シャドウマップ）。影を落とす灯を減らす、減衰半径を見直す。
2. **Lumen の品質**（ソフトウェアのレイトレース、Final Gather）。
3. **テクスチャのストリーミングプール**（2048² が多い）。エディタ側だけプールを絞る。
4. **Nanite の対象**（半透明・デカールの板は対象外にしてある）。
5. **毎フレーム描くもの**: タブレットのミニマップのシーンキャプチャ（512²、Show Only の一覧だけを描く）。板を下ろしている間に止める余地がある。
